## Técnico (específico do squad)

- **Output do squad = `clients/{slug}/` (single-write, 2026-05-14)**: TODOS os artefatos vão para a pasta do cliente. Mapeamento: brief.md → `clients/{slug}/brief/briefing.md`; strategy.md → `brief/strategy.md`; copy.md → `content/copy.md`; visual-system → `design/design-system.md` + `assets/images/`; código → `src/`; review → `deploy/qa-review.md`. Sem mirror em `squads/.../output/`. Sem versionamento v1/v2 — sobrescreve a cada run. Histórico via git.
- **Slug propagation**: step 01 captura o slug do cliente (picker com clientes existentes ou "Novo cliente" → copia `clients/_template/`) e escreve `squads/lp-generator/.runtime/current-slug.txt`. Steps 02-08 leem esse arquivo como primeira ação. Frontmatter dos steps não usa `outputFile`/`inputFile` — agentes escrevem manualmente.
- **Modo "design handoff"**: quando o Patrick fornece uma URL de design Anthropic (api.anthropic.com/v1/design/...), o bundle vem como .tar.gz. Etapas: baixar o gzip com `curl -sL -o bundle.tar.gz "<url>"` (WebFetch não serve p/ binário) → extrair com `tar -xzf` em `_build/design-fetch/` → ler README → ler chats (intenção + todas as decisões de copy estão lá) → ler o HTML de entrada e seguir imports. Pular steps de strategy/copy/design (Bruno/Carla/Diana). Davi Dev copia o conteúdo do bundle direto pra `clients/{slug}/src/`.
  - **Estrutura do bundle varia (kinevo, 2026-06-04)**: pode ser `project/` direto (NÃO `project/site/`). Conteúdo típico: `<Nome> Landing Page.html` (entrada — renomear pra `index.html`, imports são relativos e seguem funcionando), `colors_and_type.css`, `tweaks-panel.jsx`, `components/*.jsx`, `assets/*.png`. Ignorar `screenshots/`, `uploads/`, `.thumbnail` (artefatos de dev). Componentes podem se referenciar entre si fora da ordem de import óbvia (ex.: `Footer` definido dentro de `CTA.jsx`) — checar `grep` por símbolos antes de assumir que falta arquivo.
  - **Verificação do render (design handoff)**: o stack é React+Babel via CDN servindo `.jsx` por XHR, então **só roda sob HTTP** (`file://` quebra). Validar com `python -m http.server` + Playwright: app monta (`#root` com conteúdo + N `<section>`), 0 erros de console (o único warning esperado é o do Babel in-browser), e todas as logos/imgs carregam (`complete && naturalWidth>0`).
- **Patrick prefere "copy as-is"** quando o design já é HTML/CSS/JS funcional: preserva pixel-perfect, todas animações e ferramentas de iteração (tweaks-panel, image-slot). Refactor para static-single-file é follow-up opcional.
- **Modo "brand asset integration" (2026-05-15)**: quando o cliente entrega uma pasta `brief/sobre-a-marca/` com manual de marca (logos, ícones, slides de essência/missão/tom), o squad NÃO roda pipeline completo do zero. Em vez disso: (1) ler logos+slides via Read multimodal, (2) extrair copy oficial, (3) mapear pra placeholders existentes no `src/`, (4) copiar PNGs pra `src/assets/` com nomes friendly (`brand-logomarca.png`, `brand-icon-orange.png` etc.), (5) atualizar componentes que tinham placeholders. Exemplo: nova-digital — manual revelou nome real "Letícia Shibayama", essência (Alegria/proximidade + Estratégia/inovação + Humanização) que substituiu placeholders genéricos do Manifesto.
- **Decisão híbrida nome-fundadora (nova-digital, 2026-05-15)**: Patrick prefere "Letícia Shibayama" no Founder.jsx (h2, autoridade), mas "Letícia" em CTAs e atendimento ("Falar com Letícia" — proximidade). Pattern aplicável a outros clientes com fundador-cara-da-marca.
- **Logos sem versão transparente (nova-digital, 2026-05-15)**: quando o brand kit só tem logos com fundo embutido (não SVG/PNG transparente), uma saída elegante é usar a logo-com-fundo como "badge" no Nav: wrap em `.nav__brand` com `border-radius: 10px` + `overflow: hidden` + `box-shadow` sutil. Vira um stamp visual coerente com a marca. Limitação documentada: idealmente pedir ao cliente versões transparentes/SVG.
- **Modo "variante visual-first" (nova-digital-v2, 2026-05-16)**: quando o Patrick pede "menos texto, mais imagem", o pattern certo é: (1) criar novo slug `{cliente}-v2` em `clients/`, (2) copiar assets e tokens do v1, (3) redesenhar componentes com foto/ícone como âncora primária e copy como suporte. Componentes mais impactados: Hero (foto 50%), Founder (foto 50% invertida), Method (timeline horizontal com ícones, eliminar tabs), Testimonials (grid de cards vs carrossel), CTABand (substituir steps textuais por image-slot). Fast-track (só Davi + Rita) adequado quando strategy/copy já existem da v1.
- **Modo "form-na-hero" (nova-digital-v2, 2026-05-16)**: quando o Patrick pede o form CTA diretamente na Hero, o pattern é: (1) substituir `.hero__cta` + `.hero__proof` por `<form className="hero__form">` com os mesmos campos do CTABand; (2) reutilizar classes `.cta-form__field`, `.cta-form__chip` para zero duplicação de estilos; (3) adicionar `.hero__form` card em `site.css` com `box-shadow-2` e `border-radius-xl`; (4) colapsar `.hero__form-grid` para 1 coluna em `@760px`. Neutralizador de objeção como `<p className="hero__form-note">` abaixo do submit. Fast-track adequado.
- **`<legend>` em fieldset de chips (2026-05-16)**: padrão correto para acessibilidade é `<legend className="cta-form__field-legend">` dentro de `<fieldset>`, não `<span>`. CSS do legend: `float: left; width: 100%; padding: 0;` para resetar o estilo nativo. Aplicar em Hero.jsx e CTABand.jsx.
- **data-reveal em screenshots (2026-05-16)**: elementos com `[data-reveal]` partem de `opacity: 0` — em screenshots full-page via Playwright, sections off-viewport aparecem em branco. Não é bug — é comportamento esperado do IntersectionObserver. Para debugging visual, forçar `is-revealed` via `document.querySelectorAll('[data-reveal]').forEach(el => el.classList.add('is-revealed'))` antes do screenshot.
